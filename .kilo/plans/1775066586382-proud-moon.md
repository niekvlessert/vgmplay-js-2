# Fix UI Not Displaying All 917 MBM Files

## Problem Analysis

The archive extraction and file processing works correctly - all 917 files are stored in `game.files`. However, the UI only shows files until around "END_DEMO.MBM" (approximately 183 files). The issue is in the UI rendering code in `showVGMFromZip()`.

### Root Cause

In `vgmplay-library.js` line 374, the track rendering loop starts from `startIndex`:
```javascript
for (let key = startIndex; key < files.length; key++) {
```

However, the loop checks `this._fileExists(fullPath)` at line 378. If files don't exist in MEMFS, they are skipped but `game._needsOnDemandFiles` is set. The rendering may be interrupted or the deferred notice logic may interfere.

More critically, looking at the flow:
1. `_scheduleZipRender()` sets `pendingZipRender = true` and calls `_renderZipGamesNow()`
2. `showVGMFromZip()` is called for each game
3. The track rendering loop iterates through files and creates UI elements

The issue is likely one of:
1. **Performance/UI blocking**: Rendering 917 tracks synchronously may cause the browser to throttle or truncate
2. **File existence check**: `this._fileExists(fullPath)` returning false for later files
3. **Large archive deferral logic**: Lines 338-362 have deferral logic for large archives

### Key Code Locations

- `vgmplay-library.js:169` - `showVGMFromZip()` function
- `vgmplay-library.js:332-372` - Large archive and deferral logic
- `vgmplay-library.js:374-542` - Track rendering loop
- `vgmplay-library.js:161-167` - `_scheduleZipRender()` function

## Investigation Steps

1. Check if `_renderZipGamesNow()` exists and how it batches rendering

4. Check browser console for errors during rendering

## Proposed Fix

The most likely issue is that the UI rendering is synchronous and blocking. For 917 tracks, this can cause browser timeouts or truncation.

### Option A: Add Incremental Rendering
- Render tracks in batches (e.g., 50 at a time)
- Use `requestAnimationFrame` or `setTimeout` to yield to UI
- Already partially implemented via `game.lastRenderedCount`

### Option B: Virtual Scrolling
- Only render visible tracks
- Implement a scrollable list with dynamic loading
- More complex but better for large archives

### Option C: Simple Fix
- Remove or increase any hardcoded limits
- Ensure deferral logic doesn't interfere with local files
- Debug why `_fileExists()` might fail

## Recommended Approach

Start with Option C - debug the actual cause:
1. Add logging to `showVGMFromZip()` to see:

   - Count of tracks actually rendered
2. Check if `_fileExists()` is working correctly for all files
3. If it's a performance issue, implement Option A (incremental rendering)
